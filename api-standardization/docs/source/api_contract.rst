Правила HTTP-контракта
======================

Полный текст правил — ``docs/standards/API_STANDARD.md``. Здесь приведена
сводка, достаточная для использования API.

Базовый путь и URI
------------------

* Все бизнес-операции находятся под ``/api/v1``; вне версии — ``/``, ``/health``,
  ``/docs``, ``/redoc``, ``/openapi.json``.
* Пути в нижнем регистре, ресурсы во множественном числе, без глаголов и без
  завершающего слэша: ``/api/v1/projects/{project_id}/documents``.
* Документ создаётся в контексте проекта, а далее адресуется канонически:
  ``/api/v1/documents/{document_id}``.

Методы и коды
-------------

.. list-table::
   :header-rows: 1

   * - Операция
     - Метод
     - Код успеха
   * - Получить ресурс или коллекцию
     - GET
     - 200
   * - Создать ресурс
     - POST
     - 201
   * - Создать или заменить по ключу (доступ участника)
     - PUT
     - 201 / 200
   * - Частично изменить
     - PATCH
     - 200
   * - Удалить
     - DELETE
     - 204, без тела

Коды ошибок: ``401`` — нет или недействителен токен; ``403`` — недостаточно
прав; ``404`` — ресурс не найден или недоступен; ``409`` — конфликт состояния;
``413`` — слишком большое тело; ``422`` — ошибка валидации; ``429`` — превышен
лимит запросов.

Изменение состояния документа выполняется через ``PATCH`` поля ``status``.
Допустимые переходы: ``draft → published | archived``,
``published → draft | archived``, ``archived → draft``; прочие — ``409``.

Данные
------

* Поля JSON в ``snake_case``; идентификаторы — целые числа.
* Дата и время — RFC 3339 в UTC: ``2026-09-09T08:15:30Z``.
* В ``PATCH`` неуказанное поле не изменяется.
* Пароли и хэши в ответы не попадают.

Коллекции
---------

Параметры ``offset`` (≥ 0, по умолчанию 0) и ``limit`` (1…100, по умолчанию 20).
Выход за диапазон — ``422``. Ответ:

.. code-block:: json

   {"items": [], "total": 0, "offset": 0, "limit": 20}

Ошибки
------

Любая ошибка — RFC 9457 Problem Details с ``Content-Type: application/problem+json``:

.. code-block:: json

   {
     "type": "https://docs.local/problems/project-not-found",
     "title": "Project not found",
     "status": 404,
     "detail": "Project 42 does not exist or is unavailable",
     "instance": "/api/v1/projects/42"
   }

Для ``422`` добавляется массив ``errors`` с элементами ``{"field", "message"}``.
Реестр типов ошибок — :class:`app.core.problems.Problems`.
