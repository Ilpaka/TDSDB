Обзор
=====

Назначение
----------

Document Center API — внутренний сервис для ведения проектной документации.
Пользователи объединяются в проекты, внутри проекта создаются документы с
жизненным циклом ``draft → published → archived`` и автоматически
сохраняемыми версиями. Все значимые действия записываются в журнал аудита.

Предметная модель
-----------------

.. list-table::
   :header-rows: 1
   :widths: 20 80

   * - Сущность
     - Описание
   * - User
     - Учётная запись с ролью ``admin``, ``manager``, ``worker`` или ``viewer``.
   * - Project
     - Контейнер документов и единица разграничения доступа. Имеет владельца.
   * - ProjectAccess
     - Доступ участника к проекту: ``viewer`` (чтение) или ``editor`` (изменение).
   * - Document
     - Документ проекта с состоянием ``draft``, ``published`` или ``archived``.
   * - DocumentVersion
     - Снимок содержимого документа; создаётся при каждом изменении содержимого.
   * - AuditLog
     - Запись о действии пользователя.

Архитектура
-----------

Приложение построено по слоям; каждый слой зависит только от нижележащих.

.. code-block:: text

   HTTP-клиент (frontend, Swagger UI, интеграции)
          │
   ┌──────▼─────────────────────────────────────────────────────────┐
   │ Middleware: размер тела (413), защитные заголовки, CORS         │
   ├────────────────────────────────────────────────────────────────┤
   │ app/routers   — HTTP-контракт: пути, коды, схемы, OpenAPI       │
   │ app/core/deps — зависимости: сессия, пользователь, роль, limit  │
   ├────────────────────────────────────────────────────────────────┤
   │ app/services  — бизнес-правила, object-level authorization      │
   │ app/core      — безопасность, ошибки RFC 9457, rate limiting    │
   ├────────────────────────────────────────────────────────────────┤
   │ app/schemas   — Pydantic-схемы публичного контракта             │
   │ app/models    — SQLModel-модели хранилища                       │
   │ app/db        — подключение к базе данных (SQLite)              │
   └────────────────────────────────────────────────────────────────┘

* **Роутеры** не содержат бизнес-логики и не формируют тела ошибок: они
  вызывают сервис и возвращают схему ответа.
* **Сервисы** проверяют права доступа к объекту, выполняют изменения и пишут
  журнал аудита. Ошибки возбуждаются как :class:`app.core.problems.APIProblem`.
* **Обработчики ошибок** (:func:`app.core.problems.register_problem_handlers`)
  преобразуют любое исключение в Problem Details.

Структура репозитория
---------------------

.. code-block:: text

   app/            исходный код приложения
   scripts/        export_openapi.py, create_admin.py
   tests/          контрактные тесты и тесты безопасности
   frontend/       статический клиент
   docs/standards/ внутренние стандарты API, безопасности, документации
   docs/audit/     аудит, инвентаризация, OWASP, итоговый отчёт
   docs/openapi/   экспортированный контракт openapi.json
   docs/source/    исходники этой документации
