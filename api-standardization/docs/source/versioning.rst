Версионирование и устаревание
=============================

Две независимые версии
----------------------

* **Версия контракта** — ``v1``, входит в путь (``/api/v1``). Меняется только
  при несовместимом изменении контракта.
* **Версия приложения** — SemVer (``2.0.0``), указана в ``info.version``
  OpenAPI и в ответе ``GET /``. Меняется при каждом выпуске.

Совместимые и несовместимые изменения
-------------------------------------

Несовместимые: удаление или переименование операции, поля, enum-значения;
изменение типа поля или кода успешного ответа; новое обязательное поле
запроса; изменение структуры ошибки; сужение диапазона параметра.

Совместимые: новая операция; новое необязательное поле запроса; новое поле
ответа; новый тип ошибки для ранее недокументированного условия.

Процедура deprecation
---------------------

1. Операция помечается ``deprecated=True`` — в Swagger UI и ReDoc она
   отображается как устаревшая.
2. В ``description`` указываются замена и версия приложения, в которой
   операция будет удалена.
3. Изменение фиксируется в разделе ``Deprecated`` файла ``CHANGELOG.md``.
4. Операция сохраняется не менее одной minor-версии приложения.
5. Удаление фиксируется в разделе ``Removed``; если удаление несовместимо
   для действующих клиентов, вводится ``/api/v2``.

Текущее состояние
-----------------

В контракте ``v1`` устаревших операций нет. Переход с непрефиксованного
исходного API на ``/api/v1`` выполнен как несовместимое изменение версии
приложения ``2.0.0``; инструкция миграции приведена в ``CHANGELOG.md``.
