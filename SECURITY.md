# Политика безопасности

## Поддерживаемые версии

| Версия приложения | Контракт | Поддержка |
|---|---|---|
| 2.0.x | `/api/v1` | Поддерживается, исправления безопасности выпускаются |
| 1.0.x | без версии | Не поддерживается: содержит известные уязвимости (см. `docs/audit/BASELINE_AUDIT.md`). Обновитесь до 2.0 |

## Как сообщить об уязвимости

1. **Не создавайте публичный Issue или Pull Request** с описанием уязвимости.
2. Используйте приватный канал GitHub: вкладка **Security → Report a vulnerability**
   (Private vulnerability reporting) этого репозитория. Если канал недоступен —
   напишите владельцу репозитория в личные сообщения.
3. Укажите: затронутую операцию (метод и путь), версию приложения, шаги
   воспроизведения, ожидаемое и фактическое поведение, оценку последствий.
4. Срок первого ответа — 3 рабочих дня; срок исправления критической
   уязвимости — 14 дней. После выпуска исправления уязвимость описывается
   в разделе `Security` файла `CHANGELOG.md`.

## Секреты в Issue и Pull Request

Запрещено публиковать в Issue, Pull Request, комментариях, коммитах и скриншотах:

- значения `JWT_SECRET` и содержимое файлов `.env`;
- токены доступа (`eyJ...`), даже просроченные;
- пароли, в том числе тестовые от общих стендов;
- файлы баз данных (`*.db`) и журналы с данными пользователей.

Если секрет попал в репозиторий, его недостаточно удалить следующим коммитом:
секрет считается скомпрометированным и **немедленно заменяется** (для `JWT_SECRET`
это делает недействительными все выпущенные токены), после чего история
очищается.

## Работа с `.env`

- Шаблон — `.env.example`, в нём нет рабочих значений. Рабочий `.env`
  исключён через `.gitignore` и не коммитится.
- `JWT_SECRET` генерируется отдельно для каждой среды:
  `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
- В production секрет передаётся через переменные окружения или менеджер
  секретов платформы; приложение откажется стартовать с демонстрационным
  секретом, секретом короче 32 символов, `DEBUG=true` или `CORS_ORIGINS=*`.
- Права на файл `.env` на сервере — только для пользователя сервиса (`chmod 600`).

## Работа с токенами

- Токен передаётся только в заголовке `Authorization: Bearer <token>`,
  никогда — в URL или query-параметрах.
- Срок действия по умолчанию — 60 минут; не увеличивайте его без необходимости.
- Токен не логируется и не сохраняется в журнале аудита.
- Пароль первого администратора задаётся через `ADMIN_PASSWORD` или
  интерактивный ввод, а не аргументом командной строки.
